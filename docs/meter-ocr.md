# Распознавание показаний

Возможность перенесена из `feature/meter-ocr` в модуль Metering. Это вспомогательное распознавание **одного целого показания электросчётчика**, а не подтверждённая поддержка всех моделей приборов. Вода, дробная часть и многотарифные дисплеи остаются для ручного ввода. Пользователь проверяет и при необходимости исправляет результат перед отдельным нажатием «Отправить».

## Установка

Для распознавания backend должен видеть исполняемый файл Tesseract OCR. NuGet/npm-зависимости и версии платформ не менялись. На Ubuntu/Debian:

```bash
sudo apt-get update
sudo apt-get install -y tesseract-ocr
tesseract --version
```

На Windows установите Tesseract OCR из доверенного источника. Если `tesseract.exe` отсутствует в `PATH`, перед запуском проекта укажите его путь в PowerShell:

```powershell
$env:Ocr__TesseractPath = 'C:\Program Files\Tesseract-OCR\tesseract.exe'
.\start-cube.bat
```

Путь также можно задать в локальном `.env`, читаемом launcher. При отсутствии Tesseract остальное приложение работает; распознавание предлагает ручной ввод. Launcher не устанавливает сторонние программы автоматически. Для полного backend-набора тестов Tesseract необходим; Linux CI устанавливает его явно.

## Контракт и ограничения

`POST /api/v1/meters/recognize` требует действующую авторизацию и ровно один multipart-файл. Поддерживаются JPEG/PNG до 5 МиБ с проверкой сигнатуры. Несоответствующая форма запроса возвращает `400 { "message": "…" }`; поддерживаемая форма с неподходящим/нечитаемым файлом, отсутствующим движком или превышением 12 секунд возвращает `200 { "value": null, "message": "Не удалось уверенно распознать. Введите показание вручную" }`. Успех: `200 { "value": "12480", "message": null }`.

Принимается один результат из 1–12 цифр с уверенностью не ниже 80 по TSV Tesseract. Точки и запятые сохраняются при OCR, чтобы дробный дисплей не превращался автоматически в целое число. Эти эвристики не гарантируют точность на фотографиях реальных приборов: модель прибора, блики, наклон, серийные номера и качество изображения требуют отдельной проверки.

HTTP-адаптер не сохраняет показание и фотографию. Движок получает поток без зависимости от HTTP, использует временный файл и удаляет его после завершения. При отмене запроса завершает дочерний процесс; при отмене по таймауту возвращает ручной ввод. Правило разбора результата отделено от запуска внешней программы. Поздний ответ не перезаписывает ручную правку или форму после смены фото/помещения/счётчика.

## Проверка пользователем

1. Запустите проект и войдите арендатором с активным договором и электросчётчиком.
2. Откройте «Передать показания», приложите корневой `meter-example.png` и нажмите «Распознать показания». Для этого синтетического образца ожидается `12480`; показание ещё не отправлено.
3. Проверьте число, при необходимости исправьте его, затем отдельно отправьте. Существующая проверка предыдущего показания и рассмотрение сотрудником сохраняются.
4. Проверьте плохую фотографию и ввод вручную; для воды кнопка распознавания недоступна.

Автоматические проверки включают исходные четыре parser-теста, настоящий Tesseract на образце, HTTP/body/auth/ограничения файлов, отсутствие записи в БД при распознавании, отмену нативного процесса на Linux и браузерные сценарии ручного подтверждения/устаревшего ответа. Образец — синтетическое число; качество OCR на наборе реальных фотографий и физических телефонах отдельно не измерялось.
