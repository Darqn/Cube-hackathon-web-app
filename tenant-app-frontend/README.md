# КУБ — кабинет арендатора

Интерфейс на React Native / Expo 51 с веб-версией. Работает с ASP.NET Core API этого репозитория. Основной проверенный сценарий — браузер; Android/iOS требуют отдельной проверки на устройствах.

## Запуск

Нужны Node.js (проверено на 24.22.1), npm, Python 3, .NET SDK из `../global.json`, Docker Engine и Docker Compose. В подготовленной облачной среде SDK находится в `/workspace/.tools/dotnet`; `scripts/dev.sh` автоматически добавляет его в PATH.

В корне репозитория:

```bash
scripts/dev.sh setup
```

Команда создаёт приватный игнорируемый `.env`, запускает PostgreSQL, восстанавливает зависимости, собирает backend и применяет миграции. Существующие настройки и данные сохраняются.

Для первого администратора задайте `Bootstrap__Login`, `Bootstrap__Email`, `Bootstrap__Password` через защищённое окружение и выполните `scripts/dev.sh bootstrap`. Удалите эти переменные после использования. Стандартного пароля нет. Администратор использует административный API; этот интерфейс предназначен для роли Tenant.

Запустите API с CORS для веб-клиента:

```bash
bash scripts/dev-web.sh
```

В другом терминале:

```bash
cd tenant-app-frontend
npm ci
# Не перезаписывайте свой .env, если он уже существует:
cp -n .env.example .env
npm run web -- --port 8081
```

Откройте браузер через команду Expo. `EXPO_PUBLIC_API_URL` по умолчанию — `http://127.0.0.1:5080/api/v1`. После смены переменных перезапустите Expo с очисткой кэша: `npm run web -- --clear --port 8081`. Если порт или адрес фронтенда изменён, задайте соответствующие `Cors__Origins__0` и `Cors__Origins__1` перед запуском backend. Для HTTPS-страницы API также должен использовать HTTPS.

Зарегистрируйте арендатора через форму. Укажите логин, пароль от 12 символов (буквы обоих регистров, цифра, спецсимвол), организацию, корректный ИНН, email и телефон. Администратор должен одобрить заявку через `POST /api/v1/admin/registration-applications/{id}/approve`; порядок работы описан в корневом README. До одобрения вход недоступен. Для помещений, счетов и приборов нужны соответствующие записи, созданные администратором. Пустой кабинет без этих записей — нормальное состояние.

Токен хранится только в памяти: после перезагрузки страницы или истечения восьмичасовой сессии нужно войти заново. Выход вызывает серверный logout. Токены не записываются в localStorage и не попадают в ссылки на файлы.

## Проверки

```bash
npm run typecheck
npm test
EXPO_OFFLINE=1 npm run build:web
```

`EXPO_OFFLINE=1` отключает необязательные обращения Expo к его служебному API; зависимости устанавливаются обычным `npm ci` с проверкой TLS и integrity из lock-файла.

Браузерная проверка с настоящим backend и временной БД, в подготовленной облачной среде:

```bash
python3 scripts/verify-backend.py
```

Нужны доступный Docker/PostgreSQL после `scripts/dev.sh setup`, собранный Release backend, Chromium (`CHROMIUM_PATH`, по умолчанию `/usr/bin/chromium`) и свободные порты 5081/8082. Скрипт читает локальный `.env`, создаёт отдельную БД со случайным именем, временные учётные записи и файлы, собирает production-версию с очисткой Metro-кэша и проверяет кабинет на ширинах 1440 и 390 пикселей, останавливает свои процессы и удаляет тестовую БД. Рабочую БД `cube` не меняет. Скриншоты и трассы находятся в игнорируемой папке `test-results`. На другой машине установите закреплённый SDK и Chromium; при необходимости адаптируйте путь SDK в скрипте.

## Что изменено

- Добавлены конфигурация Expo, точка входа Router, алиасы TypeScript, отсутствовавшие модули и поддержка веб-сборки.
- Исправлена навигация для Expo Router 3.5, предусмотрен переход ко входу при истечении сессии.
- Реальный API включён по умолчанию. Адреса, JSON-модели, идентификаторы категорий, статусы и пагинация согласованы с backend в `src/api/backend.ts`.
- Регистрация передаёт обязательные логин, пароль и телефон; ошибки API отображаются на русском. Восстановление пароля не обещает доставку отсутствующего email-сервиса.
- Реализованы счета, документы, обращения с перепиской и вложениями, новости с раздельными прочтением и подтверждением, уведомления, заявки на аренду.
- Показания отправляются конкретному счётчику, включая выбор среди нескольких приборов. Файлы загружаются отдельным multipart-запросом, затем связываются с записью по ID.
- Защищённые документы и изображения загружаются с Bearer-заголовком. Во внешние адреса токен не передаётся.
- Обновлены палитра, контраст кнопок, ограничение ширины содержимого, мобильные отступы и области нажатия. Суммы сохраняют копейки.
- Добавлены тесты контрактов API и браузерные проверки с настоящей PostgreSQL.

## Ограничения backend

1C, Bitrix, онлайн-оплата и отправка email намеренно не подключены. При `canPay=false` интерфейс объясняет недоступность оплаты. Не создаются фиктивные платежи или подтверждения отправки писем. В production файлы ожидают проверки; исключение допускается только в Development с настройкой из локального `.env`. Размер файла — до 20 МиБ; поддерживаются PDF, JPEG, PNG, DOC/DOCX, XLS/XLSX по правилам backend.

Деморежим включается только явно: `EXPO_PUBLIC_USE_MOCK=true`. Данные demo/demo1234 не существуют на сервере. Деморежим не подтверждает работоспособность интеграции; заявки на аренду в нём отключены. Административный интерфейс не входит в этот кабинет.

Мобильный запуск: `npm run android` / `npm run ios` с совместимой Expo 51 development build. На физическом устройстве localhost указывает на само устройство: укажите доступный HTTPS API. Сборки и поведение на физических устройствах в этой работе не проверены.

## Результаты проверки

Проверены чистая установка `npm ci`, TypeScript и production-экспорт веб-версии. Все 9 контрактных тестов прошли. Оба браузерных сценария (1440×1000 и 390×844) прошли с настоящим ASP.NET Core API и временной PostgreSQL: вход одобренного арендатора, помещение и счёт, отсутствие кнопки недоступной оплаты, создание обращения, показания, скачивание закрытого документа с авторизацией, загрузка заявления, подтверждение новости и выход. Проверка не обнаружила горизонтального переполнения главного экрана и ошибок JavaScript в этих сценариях. Временная БД удалена после выполнения.

Проверки не охватывают все возможные бизнес-состояния, физические Android/iOS-устройства, production-инфраструктуру и отключённые внешние интеграции.
