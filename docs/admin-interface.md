# Административная панель и рабочий кабинет

Панель реализована по разделам 2, 8, 11, 14 и 23 технического задания из `Техническое задание приложение.docx`. Используется общий фронтенд Expo и существующая ASP.NET Core авторизация. Внешние 1С, Битрикс, платежи и почта остаются отключёнными согласно ограничениям проекта.

## Вход

Запуск не изменился:

```bash
# Корень репозитория
scripts/dev.sh setup
bash scripts/dev-web.sh

# Другой терминал
cd tenant-app-frontend
npm ci
npm run web -- --clear --port 8081
```

Войти можно через общую форму логина и пароля. После проверки серверной роли:

- `Admin` открывает `/manage/overview` с полной панелью управления.
- `Staff` открывает рабочий кабинет: назначенные обращения, счётчики и история показаний по ответственному направлению, профиль.
- `Tenant` открывает прежний кабинет арендатора.

Роль не выбирается пользователем в форме и не берётся из localStorage. Сессия хранится в памяти. Обновление страницы требует повторного входа. Прямой переход в недоступный раздел возвращает пользователя в его кабинет; API отдельно проверяет права каждого запроса.

Для первого администратора задайте `Bootstrap__Login`, `Bootstrap__Email`, `Bootstrap__Password` в защищённом окружении и выполните из корня `scripts/dev.sh bootstrap`. Пароль — минимум 12 символов, прописная и строчная буквы, цифра и спецсимвол. Значения не нужно добавлять в Git. Команда откажется работать, если администратор уже существует. После создания удалите переменные Bootstrap из окружения.

Сотрудника создаёт администратор в разделе **Пользователи и роли → Создать сотрудника**. Укажите логин, email, ФИО и пароль. Для доступа к обращениям назначьте его ответственным по категории или конкретному обращению. Учётных записей со стандартным паролем нет.

## Разделы и сценарии

| Раздел | Реализованные действия |
| --- | --- |
| Обзор | Число обращений, задач в работе и просроченных задач; административные сводки по организациям, свободным помещениям и заявкам |
| Заявки на регистрацию | Проверка организации, ИНН и контактов; подтверждение с созданием организации либо явной привязкой к существующей с совпадающим ИНН; блокировка/разблокировка заявки |
| Арендаторы | Создание и редактирование организации, блокировка и восстановление доступа; карточка с логинами пользователей, контактами, помещениями, договорами, счетами, документами и обращениями |
| Помещения | Создание и редактирование типа, адреса, корпуса, секции, этажа, площади, цены, описания и статуса; фотографии через связанное объявление |
| Договоры аренды | Привязка помещения к организации с датами и номером договора; завершение или расторжение с освобождением помещения |
| Документы | Загрузка договоров, допсоглашений, актов, заявлений, счетов-фактур, УПД, шаблонов и прочих документов; привязка к организации, договору и помещению; скачивание, архивирование и восстановление; рассмотрение заявлений |
| Счета | Ручное выставление счёта по типу начисления, даты, сумма с копейками, привязка PDF; отображение оплаченного остатка и срока оплаты |
| Обращения | Все обращения для администратора, только назначенные для сотрудника; поиск, фильтры по организации, помещению, категории, ответственному и статусу; сроки и ответственный; допустимые переходы статусов; публичные ответы, внутренние заметки, история, защищённые вложения |
| Счётчики и показания | Добавление прибора к действующему договору, история, просмотр фото администратором, принятие/отклонение с комментарием, обоснованная коррекция базы без перезаписи истории |
| Объявления | Создание, редактирование, публикация/скрытие, архивирование, фотографии, изменение цены и статуса связанного помещения |
| Новости и оповещения | Категории из ТЗ, важность, текст, аудитория по организациям/помещениям/корпусу/секции/этажу, черновики, публикация сейчас или по времени, срок актуальности, снятие с публикации очисткой даты публикации, архивирование, вложения, просмотр отметок открытия и подтверждения |
| Пользователи и роли | Просмотр ролей и логинов, создание сотрудников, блокировка и восстановление доступа; самоблокировка запрещена сервером |
| Маршрутизация | Ответственный по каждой из шести категорий ТЗ; назначение применяется к новым обращениям |
| Журнал действий | Просмотр доступных серверных записей аудита с исполнителем, датой и идентификатором записи |
| Интеграции | Фактический статус отключённых систем и сохранённые события, ожидающие подключения |
| Мой профиль | Просмотр учётной записи, редактирование ФИО и телефона, смена пароля с повторным входом |

На широком экране используется боковая навигация; на узком — раскрывающееся меню. Формы имеют обязательные поля, проверки дат, чисел и паролей, защиту от повторной отправки и вывод серверных ошибок на русском. Списки загружаются с учётом серверной пагинации и отображаются страницами по 20 записей.

## Разграничение доступа

Добавлены административные списки `GET /api/v1/admin/leases` и `GET /api/v1/admin/meters`: они доступны только роли Admin. Старые арендаторские маршруты не расширены до общего доступа.

`GET /api/v1/staff/meters` и `/api/v1/staff/readings` доступны сотрудникам по явно назначенной категории: электричество → электрические приборы, водоснабжение/отопление → водяные. Изменение ответственного сразу меняет доступ к истории. Это доступ к типу приборов по направлению во всех организациях, а не право администратора. Сотрудникам других направлений возвращается пустой список. Изменение и проверка показаний остаются полномочием администратора.

Комментарии и статусы применяются к назначенному обращению. Внутренние заметки отделены от ответов арендатору; backend исключает их из арендаторского ответа. При смене статуса, ответственного или базы счётчика передаётся серверная версия записи. Конфликт требует обновления карточки.

Документ сначала загружается для выбранного арендатора, затем связывается с записью. Если файл находится в карантине, документ/счёт ещё не создаётся; интерфейс сообщает о проверке. Не отключайте production-карантин ради загрузки. Фотографии помещения хранятся в его объявлении: если объявления ещё нет, кнопка фотографий создаёт скрытую публикацию.

## Ограничения действующего backend

- Нет произвольного повышения роли существующего пользователя и создания дополнительных администраторов через панель; первоначальный администратор создаётся Bootstrap-командой. Права сотрудника задаются блокировкой, назначениями обращений и маршрутизацией.
- Архивирование документов обратимо. Архивирование новостей и объявлений не удаляет данные, но их восстановление сервером не предусмотрено; для временного скрытия используйте черновик/снятие публикации. Удаление документов заменено разрешённым ТЗ архивированием.
- Получатели новости отображаются по текущим организациям и действующим договорам. Это не подтверждение доставки. Сервер возвращает до 1000 отметок прочтения; снимок исторической аудитории и отчёт о доставке email/push/SMS отсутствуют.
- Аудит показывает существующие серверные события (создание сотрудника, одобрение регистрации, блокировка/разблокировка пользователя). Полный аудит каждого изменения, резервное копирование и инфраструктурный HTTPS требуют отдельной backend/эксплуатационной работы.
- Отправка во внешние системы, банковская оплата, email, SMS и native push не эмулируются. Рабочий кабинет обновляет обращения и показания опросом сервера; отдельный центр уведомлений сотрудников backend пока не предоставляет.
- Защищённые фотографии показаний доступны администратору. Рабочий кабинет ответственного сотрудника показывает историю значений и результаты проверки.

## Проверки

```bash
cd tenant-app-frontend
npm run typecheck
npm test
EXPO_OFFLINE=1 npm run build:web -- --clear
python3 scripts/verify-backend.py

# Из корня репозитория
scripts/dev.sh test
```

Браузерный скрипт собирает production-версию и проверяет её с отдельной временной PostgreSQL. В конце он удаляет тестовую БД и останавливает свои процессы; рабочая БД не изменяется. Потребуются свободные порты 5081/8082 и Chromium. См. также инструкции `tenant-app-frontend/README.md`.

## Проверенные результаты

На 5 ноября 2026 года: Release-сборка backend без предупреждений и ошибок; 40 backend-тестов пройдено, без пропусков; проверка TypeScript и 16 frontend-тестов пройдены. Пять браузерных сценариев прошли на настоящем API и временной PostgreSQL: административные операции, рабочий кабинет и изоляция внутренних заметок, мобильная панель с рассмотрением показаний, кабинет арендатора на широком и узком экране. Проверено, что Staff получает 403 на административный API. Production-версия интерфейса собирается успешно. Тестовые БД удалены после выполнения. Физические Android/iOS-устройства и реальные внешние интеграции не проверялись.
