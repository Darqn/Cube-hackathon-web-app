# КУБ — кабинет арендатора

Интерфейс на React Native / Expo 51 с кабинетами арендатора, администратора и сотрудника. Работает с ASP.NET Core API этого репозитория. Основной проверенный сценарий — браузер; Android/iOS требуют отдельной проверки на устройствах.

## Запуск

Нужны Node.js (проверено на 24.22.1), npm, Python 3, .NET SDK из `../global.json`, Docker Engine и Docker Compose. В подготовленной облачной среде SDK находится в `/workspace/.tools/dotnet`; `scripts/dev.sh` автоматически добавляет его в PATH.

В корне репозитория:

```bash
scripts/dev.sh setup
```

Команда создаёт приватный игнорируемый `.env`, запускает PostgreSQL, восстанавливает зависимости, собирает backend и применяет миграции. Существующие настройки и данные сохраняются.

Для первого администратора задайте `Bootstrap__Login`, `Bootstrap__Email`, `Bootstrap__Password` через защищённое окружение и выполните `scripts/dev.sh bootstrap`. Удалите эти переменные после использования. Стандартного пароля нет. После входа администратор попадает в панель управления, сотрудник — в рабочий кабинет. Подробности и соответствие ТЗ: [административный интерфейс](../docs/admin-interface.md).

Запустите API с CORS для веб-клиента:

```bash
bash scripts/dev-web.sh
```

В другом терминале:

```bash
cd tenant-app-frontend
npm ci
# Не перезаписывайте свой .env, если он уже существует:
cp -n .env.example .env
npm run web -- --port 8081
```

Откройте браузер через команду Expo. `EXPO_PUBLIC_API_URL` по умолчанию — `http://127.0.0.1:5080/api/v1`. После смены переменных перезапустите Expo с очисткой кэша: `npm run web -- --clear --port 8081`. Если порт или адрес фронтенда изменён, задайте соответствующие `Cors__Origins__0` и `Cors__Origins__1` перед запуском backend. Для HTTPS-страницы API также должен использовать HTTPS.

Зарегистрируйте арендатора через форму. Укажите логин, пароль от 12 символов (буквы обоих регистров, цифра, спецсимвол), организацию, корректный ИНН, email и телефон. Администратор одобряет заявку в панели: «Заявки на регистрацию → Подтвердить доступ». До одобрения вход недоступен. Для помещений, счетов и приборов нужны соответствующие записи, созданные администратором. Пустой кабинет без этих записей — нормальное состояние.

Токен хранится только в памяти: после перезагрузки страницы или истечения восьмичасовой сессии нужно войти заново. Выход вызывает серверный logout. Токены не записываются в localStorage и не попадают в ссылки на файлы.

## Проверки

```bash
npm run typecheck
npm test
EXPO_OFFLINE=1 npm run build:web
```

`EXPO_OFFLINE=1` отключает необязательные обращения Expo к его служебному API; зависимости устанавливаются обычным `npm ci` с проверкой TLS и integrity из lock-файла.

Браузерная проверка с настоящим backend и временной БД, в подготовленной облачной среде:

```bash
python3 scripts/verify-backend.py
```

Нужны доступный Docker/PostgreSQL после `scripts/dev.sh setup`, собранный Release backend, Chromium (`CHROMIUM_PATH`, по умолчанию `/usr/bin/chromium`) и свободные порты 5081/8082. Скрипт читает локальный `.env`, создаёт отдельную БД со случайным именем, временные учётные записи и файлы, собирает production-версию с очисткой Metro-кэша и проверяет кабинет на ширинах 1440 и 390 пикселей, останавливает свои процессы и удаляет тестовую БД. Рабочую БД `cube` не меняет. Скриншоты и трассы находятся в игнорируемой папке `test-results`. На другой машине установите закреплённый SDK и Chromium; при необходимости адаптируйте путь SDK в скрипте.

## Веб-оформление

Светлая тёплая палитра, золотистые акценты, тонкие линии и компактные карточки применяются ко всем кабинетам. Фирменный блок «Дальреммаш» находится в шапке; брендирование «Куб» в интерфейсе отсутствует.

На широком экране кабинет арендатора использует верхнюю навигацию и двухколоночный обзор. На небольших экранах сохраняется нижняя навигация. Вход, регистрация и восстановление доступа используют общий адаптивный каркас. Администратор и сотрудник сохраняют свои разделы и права доступа.

Проверка адаптивности форм на ширинах 320, 390, 768, 1024 и 1440 пикселей включена в `tests/browser/design.spec.ts` и общий браузерный запуск. Оригинальные ограничения интеграций остаются в силе: интерфейс не предлагает неподключённую оплату и не обещает отправку писем.

## Что изменено

- Добавлены конфигурация Expo, точка входа Router, алиасы TypeScript, отсутствовавшие модули и поддержка веб-сборки.
- Исправлена навигация для Expo Router 3.5, предусмотрен переход ко входу при истечении сессии.
- Реальный API включён по умолчанию. Адреса, JSON-модели, идентификаторы категорий, статусы и пагинация согласованы с backend в `src/api/backend.ts`.
- Регистрация передаёт обязательные логин, пароль и телефон; ошибки API отображаются на русском. Восстановление пароля не обещает доставку отсутствующего email-сервиса.
- Реализованы счета, документы, обращения с перепиской и вложениями, новости с раздельными прочтением и подтверждением, уведомления, заявки на аренду.
- Показания отправляются конкретному счётчику, включая выбор среди нескольких приборов. Файлы загружаются отдельным multipart-запросом, затем связываются с записью по ID.
- Защищённые документы и изображения загружаются с Bearer-заголовком. Во внешние адреса токен не передаётся.
- Обновлены палитра, контраст кнопок, ограничение ширины содержимого, мобильные отступы и области нажатия. Суммы сохраняют копейки.
- Добавлены тесты контрактов API и браузерные проверки с настоящей PostgreSQL.

## Ограничения backend

Распознавание целых показаний электросчётчика доступно по кнопке после выбора фото. Результат нужно проверить и отдельно отправить. Backend требует Tesseract; без него сохраняется ручной ввод. [Установка, образец и ограничения](../docs/meter-ocr.md).

1C, Bitrix, онлайн-оплата и отправка email намеренно не подключены. При `canPay=false` интерфейс объясняет недоступность оплаты. Не создаются фиктивные платежи или подтверждения отправки писем. В production файлы ожидают проверки; исключение допускается только в Development с настройкой из локального `.env`. Размер файла — до 20 МиБ; поддерживаются PDF, JPEG, PNG, DOC/DOCX, XLS/XLSX по правилам backend.

Деморежим включается только явно: `EXPO_PUBLIC_USE_MOCK=true`. Данные demo/demo1234 не существуют на сервере. Деморежим не подтверждает работоспособность интеграции; заявки на аренду в нём отключены. Административная панель и рабочий кабинет открываются автоматически по серверной роли. Роль нельзя выбрать в форме входа.

Мобильный запуск: `npm run android` / `npm run ios` с совместимой Expo 51 development build. На физическом устройстве localhost указывает на само устройство: укажите доступный HTTPS API. Сборки и поведение на физических устройствах в этой работе не проверены.

На Windows `start-cube.bat` открывает отдельное окно **Cube - Expo QR** и согласует адрес Metro/API для локальной Wi-Fi/LAN сети. QR можно повторно показать клавишей `c`. [Инструкция по QR, выбору IP, localhost и tunnel](../docs/windows-expo-qr.md). В development LAN используется HTTP на частном адресе компьютера; production-доступ и совместимость Expo SDK 51 на физическом устройстве проверяются отдельно.

## Результаты проверки

Проверены TypeScript и production-экспорт веб-версии. Все 20 frontend-тестов и 48 backend-тестов прошли. Восемь браузерных сценариев прошли с настоящим API и временной PostgreSQL: три административных, три сценария отдельного кабинета сотрудника и два сценария арендатора. Проверены приватность внутренних файлов по прямой ссылке, отзыв прав, уведомления и конкурентная проверка показаний. Временные БД удалены. Новые внешние зависимости и миграции для кабинетов не добавлялись.

Проверки не охватывают все возможные бизнес-состояния, физические Android/iOS-устройства, production-инфраструктуру и отключённые внешние интеграции. Подробности — в инструкциях административного и рабочего интерфейса.

## Панель администратора и кабинет сотрудника

Вход через общую форму. Администратор управляет заявками на регистрацию, организациями, помещениями, договорами, документами, счетами, обращениями, счётчиками, объявлениями, новостями, пользователями и маршрутизацией. Сотрудник видит назначенные обращения и историю счётчиков по своему направлению. [Полная инструкция, сценарии и ограничения](../docs/admin-interface.md).

## Отдельный кабинет сотрудника

Пользователь с ролью `Staff` автоматически открывает `/staff/overview`: очередь назначенных обращений, сроки и фильтры, центр уведомлений, ответы и внутренние файлы, счётчики, фото и рассмотрение показаний по направлению, профиль. [Русская инструкция по всем рабочим сценариям](../docs/employee-interface.md). После обновления пересоберите и перезапустите backend, затем запустите Expo с `--clear`. Новые внешние зависимости и миграции для кабинета не требуются.
